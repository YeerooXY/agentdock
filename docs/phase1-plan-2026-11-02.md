## Workstreams and file ownership

No file has two owners. `electron/main.cjs` and `electron/preload.cjs` belong only to A, the integrator.

### A. State store and sync protocol (integrator)
Owns: new `electron/state-store.cjs`, `electron/state-protocol.cjs` (types, validation), `electron/projections.cjs` (desktop and phone allowlisted views), contract fixtures under `tests/fixtures/state/`, `electron/main.cjs`, `electron/preload.cjs`, `electron/mobile.cjs`, `electron/mobile-stream.cjs`.
Steps:
1. Freeze the contract: slice list with one writer each, `{byId, order}` collections, change envelopes (`patch`, `replace`, `reset`), `hello{lastRev}`, epochs, acknowledgements. Shared Node and Dart fixtures. Other workstreams code against these fixtures.
2. Store with coalescing per tick, one revision bump per changed slice, transactions, separate desktop and phone projection revisions. Seed from persisted state.
3. Legacy adapter: the existing full snapshot is built from the store, so nothing visible changes yet.
4. `/v2/events` for the phone and v2 IPC for the desktop, opt-in, with resume from `lastRev` or reset, one unacknowledged batch per connection, high and low water marks, async gzip. Keep `/v1/events` working. Server ping every 15 s with a background grace.
5. Default to v2 after parity checks, then remove full-snapshot publishing.
Acceptance: unit tests for gaps, duplicates, restart, deletion, slow acknowledgements, chunked resets, revocation; credentials never enter a slice (allowlisted DTOs only).

### B. Event correctness and tasks
Owns: `electron/task-loop.cjs`, `electron/projects.cjs`, `electron/task-plan.cjs`, `electron/results.cjs`, their tests.
Steps:
1. `persist(job)` emits; `changed()` becomes an alias. Failed writes report a storage error.
2. Remove `refresh()` from `snapshot()`; schedule verification at startup, on repository change and on a bounded timer; discard results whose task generation changed.
3. Write each task's structured outcome JSON next to the existing report: verdict, one-line outcome, changed files, checks, open items. Strip `<tool_call>` markup from summaries. The markdown report stays as the technical log.
4. Task acknowledge and dismiss fields, used by the attention count.
5. Investigate the pre-existing failing test.
Acceptance: every persistence path emits exactly once; snapshots are pure reads.

### C. Desktop consumer and Usage rows
Owns: new `src/state-client.js`, new `src/core/dom.js` (keyed patching), `src/app.js`, `src/task-loop-ui.js`, `src/workbench-ui.js`, `src/projects-ui.js`, `src/project-plan-ui.js`, desktop smoke scripts.
Steps:
1. State client that applies v2 changes and lets each page subscribe to its slices. Pages patch keyed nodes in place and keep focus, typed text, selection, scroll, `<details>` and open selects; a removed focused control hands focus to its successor. This replaces the per-form restore code and the dropdown guard.
2. Usage page: one row per account under a provider header, as specified in the research doc (tightest limit first, "Unknown" never shown as 0%, stale rows kept with their age, Refresh and Hide per row). Remove the per-provider account select.
3. Task result cards from the outcome JSON: title, outcome, verdict, files, checks, open items, actions; the technical log behind a disclosure.
4. Remove Tasks polling; replace remaining middle dots.
Acceptance: headless checks for Tab, Shift+Tab, Enter and Space during live updates; screenshots of current, stale, unknown, error and empty Usage states.

### D. Phone consumer
Owns: `mobile/lib/**`, `mobile/test/**`.
Steps:
1. Typed slice models (`Session`, `Task`, `UsageAccount`, `Project`) and a v2 client against A's fixtures, keeping v1 as fallback.
2. Separate notifiers for connection, appearance, selection and each terminal; terminal output repaints only its console. Build-count tests prove Projects and the app shell do not rebuild on terminal output.
3. Tasks on the phone from the `tasks` slice; Projects and Results subscribe instead of reloading on reconnect.
4. Usage rows per account, same rules as desktop.
5. Model and effort sheet driven by the provider's switch method (resume, relaunch, none) from E.
Acceptance: Flutter analyze and tests; widget build counters; 320 px and large-text layouts.

### E. Provider registry, settings and usage readers
Owns: new `electron/providers/*.cjs` and `electron/providers/index.cjs`, `electron/cli-catalog.cjs`, `electron/cli-launch.cjs`, `electron/provider-account-capabilities.cjs`, `electron/model-selection.cjs`, `electron/sessions.cjs`, `electron/subscription-usage.cjs`, `electron/*-usage.cjs` readers, `electron/account-profiles.cjs`, their tests.
Steps:
1. Registry with a schema; wrap the current catalog and capability rows as adapters. Snapshot test proves the derived tables are unchanged.
2. Normalized `UsageReading` and server-side staleness; `not-isolated` and `no-quota` states. Pass the per-account environment to the six readers that use the global one, or report `not-isolated` until verified. Derive the usage flag from the reader map.
3. Settings adapter (`switch`, `listModels`, `launchArgs`, `resumeArgs`, `captureSessionId`, `confirmIdentity`). Move Claude and Codex argument building out of `sessions.cjs`; generalize switching to call the adapter.

   E3 done (2026-11-03): `electron/provider-settings.cjs` exports `settingsAdapter(provider)` with `launchArgs(ctx)` and `switchMethod`. ### F. Scheduler (starts after B step 2)
Owns: new `electron/scheduler.cjs`, `electron/capacity-reservations.cjs`, `electron/task-contracts.cjs`, `electron/delegation.cjs`, `electron/local-assist.cjs`, and `electron/task-loop.cjs` and `electron/task-plan.cjs` once B hands them over.
Steps:
1. Persisted jobs, resource requests and leases; global, per-account-group, local and check capacity from Settings.
2. Route every execution entry point through admission; remove the copied caps. Queue instead of failing, with position and the blocking reason ("Waiting for account", "Waiting for files").
3. Current-branch work locks the checkout; worktree jobs and split subtasks with disjoint owned files run in parallel. Creating worktrees still needs the owner's authorization.
4. Merge-back lease per repository and target branch, checks on the exact merged tree, crash-safe intent records.
Acceptance: mocked-provider tests for contention, cancellation, crashes and stale merges.

F1-F2 implementation, 4 November 2026: `scheduler.cjs` persists request metadata and leases, interrupts stale requests on startup, and admits model turns, split subtask lifetimes, checks, cross-agent reviews and local assist. Owner reservations and current-branch repository locks remain enforced. FIFO replaces equal-time project rotation. Integration: construct one `CapacityReservations(owners, { root, getSettings, workers, active })` and supply it as `admission` to TaskLoop and Delegation; assign it to `workbench.localAssist.admission`. Main-process wiring belongs to the lead. Verification: 83 focused in-process tests pass. Required full tests and build hit `spawn EPERM`; Docker desktop checks hit a denied Buildx lock. Health: no duplicate windows in owned files and no added long functions. Local execution was skipped because this assigned portion explicitly requires direct implementation without delegation.
