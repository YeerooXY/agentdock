# Playtime study timer

The course context reads `study-timer.json` from the Playtime profile passed when the console is opened. Playtime publishes this atomic snapshot during normal runtime refreshes and writes an idle snapshot on clean exit. The reader never controls the timer or changes profile files.

Version 1 provides observation time, selected course ID and subject, running/paused/idle state, focus/break phase, session start, phase deadline, pause time and configured durations. The context calculates remaining milliseconds at its read time, freezing paused timers. Snapshots older than 15 seconds are stale; missing or malformed files are unavailable. A different course is inactive and exposes no session details. Timer state does not establish mastery or attendance.

The lightweight `dock_context({detail:"study"})` refresh uses the same timer reader. Request it when entering or resuming study, after breaks or reflection changes, and before time-dependent claims. Ordinary tutoring answers in supported quiet-study consoles reuse their course context. A previously read deadline cannot establish whether Playtime is still running or has paused.
