## Workflow findings

The Paddock agent attempted local_assist four times. Each failed because the isolated profile had no configured local endpoint. It never called task_candidates or start_task. The only skill entry read was web-ux-ui. It did not load pstack, ponytail, project-documentation or thermo-nuclear. The shared prompt says direct work is allowed when a worker adds no useful capability, but no mandatory routing decision or candidate check follows a local failure. Tool and skill availability therefore did not establish the intended worker workflow. The lead skill delivery limit also excluded the sixth skill, thermo-nuclear, from automatic inline delivery.

This is an observation about the current optional-guidance behavior, not evidence for or against distributed implementation. Retain the outcome without rerunning or patching it. A future routing change should make eligible-route discovery and an explicit direct/delegate decision observable before substantial implementation, reuse readiness readings, and preserve direct handling for small work. No routing source change was made in this investigation.

## Quality evidence

Both applications implement the four requested capabilities and pass their own final tests. Plain also passed an independent rerun of its six headless desktop/phone browser tests. Paddock's original logs report passing desktop/iPhone browser suites; those were not independently rerun here. Test counts alone do not rank quality.

One native Sonnet reviewer audited anonymized backend snapshots, with no fixes or nested review. Report: .build/stockroom-audit/review.md. Usage: 180,111 input including 122,631 cached, 14,892 output, about 2.2 minutes. This is shared assessment overhead; exact resolved-model pricing was not independently established.

A held-out integrity check on disposable files reproduced one reviewer finding: delete the last transfer movement while retaining its receipt. Paddock accepts the file and reports the transfer retry already applied; plain rejects the inconsistent file. This is a corruption/tampering scenario, not an API-reachable partial transfer. The plain server defaults to listening on all interfaces without authentication, whereas Paddock defaults to loopback. The reviewer also found optimistic-concurrency and scaling risks; migration compatibility concerns were not verified against actual earlier-version code. No numeric winner or bug-free claim is warranted.
