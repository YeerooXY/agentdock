# Web UX/UI

Help people understand a product, make a correct decision and complete their task. Use the project's brief, brand, canon and current implementation first; this skill supplies research-backed defaults and checks.

## Work method

1. Establish audience, entry route, immediate task, main action, evidence and success condition. Ask only when a missing fact changes the work.
2. Define the complete journey, including empty, waiting, error and success states, before polishing a screen.
3. Choose the composition from the information relationship. A shipped competitor pattern is a hypothesis, not proof.
4. Build with real content, semantic color roles and existing components. Every visible control needs a real outcome.
5. Verify the rendered journey at phone, tablet and desktop widths. State which checks were emulated and which still need real devices.

Explain consequential recommendations as observation, user consequence, change and verification.

## Evidence rules

- Label claims as standard, research finding, platform guidance, observation, working default or hypothesis.
- A screenshot shows composition. It does not prove keyboard use, speed, accessibility conformance or conversion.
- Never invent testimonials, customers, statistics, progress, certifications or business details.
- Recheck numerical thresholds, legal requirements and browser support against current primary sources before reporting them.
